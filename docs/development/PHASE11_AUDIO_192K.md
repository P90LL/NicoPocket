# 標準音質の192 kbps上限化

## 仕様変更

`codex/feature/metadata-edit`上で音質仕様を変更した。ユーザー指定により、以前の「標準でも192 kbps超しかなければ音声コピー」から、192 kbps超の標準音質だけを再エンコードする仕様へ変更した。コミット・プッシュは実行していない。

- 標準: 192 kbps以下の既存候補の最高品質を優先する。該当候補がなく192 kbps超を取得した場合はAAC-LC 192 kbpsへ再エンコードする。
- 192 kbps以下: 音声コピー。128 kbpsを192 kbpsへ引き上げない。
- 高音質: 利用可能な最高品質を選び、音声コピーを維持する。
- 品質不明: 不明なビットレートを推測せず、既存の取得・音声コピーへ戻す。

## 接続

既存audio rendition選択結果を取得ジョブの`audioSelection`にも保持し、FFmpeg開始時に同じ選択結果を使用する。標準かつ確認済み入力bitrate > 192の場合だけ以下を指定する。

```text
-c:a aac -b:a 192k -profile:a aac_low
```

それ以外は`-c:a copy`。同梱FFmpegのAACエンコーダを再利用する。新しい変換基盤や取得経路は追加していない。FFmpeg出力ガードはM4A形式を維持し、音声コピーまたは上記のAAC-LC 192 kbpsだけを許可する。

Metadata、JPEG attached picture、M4A専用保存、MIME audio/mp4、タイトル正規化、仮想FS後始末と実行管理は維持する。Artwork画像はコピーのまま。192 kbpsはエンコード目標値であり、短い音源や低い複雑度では実測平均値が異なる。

## 変更ファイル

- `nico_downloader/pocket/audio-quality.js`: 入力品質と選択モードに応じた音声出力引数。
- `nico_downloader/pocket/aac-bridge.js`: 選択結果を取得ジョブへ保持。
- `nico_downloader/dist/utils.js`: 条件付き192 kbpsエンコードと出力ガード。既存の改行形式を保持。
- `nico_downloader/pocket/window.js`、`window.html`、`nico_downloader/options.html`: 音質説明。
- `README.md`: 現行音質表と説明。
- 本記録。

## 合成検証

分離した検証用Chromeで同梱ffmpeg.wasmと合成HLSを使用した。128のみ、128 / 192、128 / 192 / 256、256のみ、品質不明を標準／高音質の計10ケースで確認した。

- 256品質入力のみの標準で再エンコードされ、AACバイト列が変わることを確認した。
- 8秒の合成音源で出力AAC-LC平均192045 bpsを確認した。音声データは218752 bytesから195709 bytesへ減少した（約10.5%減）。音声内容・入力の実際の平均bitrateによって削減率は異なる。
- 高音質と192 kbps以下は入力AACとバイト一致した。品質不明も従来のフォールバックと音声コピーを維持した。
- 10ケースでMetadata、768×768 attached picture、タイトルと保存名、M4Aのみ保存、全体デコード、シーク、仮想FS後始末を確認した。
- 同じ動画で繰り返し保存し、SPA切替時に標準音質へ戻ることを確認した。

## 未確認事項

今回の変更は実サイトでは未確認。実サイトで192 kbps超の音源が選択される動画について、標準の192 kbps化・高音質の維持・容量・Metadata／Artworkを確認する。

入力品質が不明な場合は192 kbps超と判定できないため再エンコードしない。現在の仕組みは品質IDに明示されたbitrateで判定し、音源全体を別途解析する処理は追加していない。
