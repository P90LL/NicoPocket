# にこぽけ（NicoPocket）

ニコニコ動画の音声を取得し、音質調整、正方形ジャケットの生成、メタデータ付きM4Aへの保存を行う、個人利用向けChrome拡張機能の開発プロジェクトです。`masteralice3104/nico_downloader` をフォークし、既存の取得・保存処理をベースにNicoPocket独自の機能を追加していきます。

> [!IMPORTANT]
> 現在のソースはフォーク元の構成をベースとしています。本READMEの「目標要件」「設定」「技術方針」「受け入れ条件」は、これからこのリポジトリで実現する内容です。記載されている独自機能が利用可能になったことを意味しません。

## 基本方針

- `nico downloader` の既存の実装状態を尊重し、独自機能の追加に必要な改修・追加を行う。取得・保存処理や構成の変更は、既存実装を確認したうえで必要な範囲に限定する。
- 公開する文書・成果物には、環境固有のローカルパスや個人情報、資格情報、内部の検証ログを含めない。
- デザインとユーザー向け仕様は、`nico-pocket-proj` で決定された内容を使用する。画面デザイン・表示文言・操作フローは同プロジェクトのUI/UXモック、ユーザー向け動作・制約・受け入れ条件は同プロジェクトの仕様書を基準とする。モックの実装方式は本体の実装方式を固定するものではない。

### Cookie送信に関する現状の差

NicoPocketの目標は、アカウント連携やログイン資格情報の取得・転用を前提とせず、拡張機能の取得通信でCookieを送信しないことです。

現在の `nico_downloader/func/ndl.js` の `DownloadTextWithCookie` には `fetch(URL, { credentials: 'include' })` があり、この目標と一致していません。これはCookieを送信可能な設定がコードにあるという確認であり、配信元がCookieを必須とする証拠ではありません。Cookieなしで実媒体を取得できるかは未検証です。

## 目標要件

本章は `nico-pocket-proj` で決定されたNicoPocketのユーザー向け仕様を整理したものです。実装方法の都合だけで要件を変更せず、成立しない条件や仕様の矛盾は未確定事項として整理します。

### 1. 音声取得と音質

- ログイン不要で取得できる媒体を対象に、取得経路と必要なサイトアクセス権限を検証する。
- メタデータ、配信リスト、音声、画像等の取得通信でCookieを送信しない。Cookieを送信する再試行も行わない。
- 音質は「最高音質」「160 kbps上限」「128 kbps上限」の3種類から選択する。
- 最高音質ではAACを再エンコードせず、入力形式・コンテナが許す限りストリームコピーする。
- 上限指定時も、元音源が指定値以下なら不要な再エンコードを行わない。

| 元音源 | 指定 | 処理 |
| ---: | ---: | --- |
| 225 kbps | 160 kbps上限 | 160 kbpsを上限に圧縮 |
| 150 kbps | 160 kbps上限 | 元の150 kbpsを維持 |
| 225 kbps | 128 kbps上限 | 128 kbpsを上限に圧縮 |
| 107 kbps | 128 kbps上限 | 元の107 kbpsを維持 |

圧縮に失敗した場合は同じ条件で設定回数まで再試行し、それでも失敗した場合は最高音質へ自動的に戻して警告を表示します。取得できた音声の保存を継続し、音声取得や最終的な保存にも失敗した場合は該当ジョブだけを停止します。

### 2. M4Aとメタデータ

完成したM4Aには次の内容を格納します。

| 項目 | 内容 |
| --- | --- |
| `title` | 動画タイトル |
| `niconico_id` | ニコニコ動画の動画ID |
| `source_url` | 取得元の動画URL |
| `cover art` | 加工後の正方形JPEGジャケット |

独自タグはM4A／MP4コンテナ内部に保持し、macOS Finderの拡張属性等のOS固有属性には依存しません。キーの格納方式とプレイヤー互換性は、出力ファイルを読み戻して検証します。

### 3. サムネイルとクロップ

- クロップは1:1固定とし、確定範囲をJPEGジャケットとして埋め込む。
- 画像認識は初期状態でONとし、検出結果から画像内に収まるクロップ候補を提示する。
- 解析失敗、検出不能、低信頼度、不適切な候補、画像認識OFFの場合は中央クロップへ戻す。
- 検出結果は汎用的な重要領域を保証するものと扱わず、表示文言は「対象を検出しました」とする。
- ドラッグで位置、四隅のハンドルでサイズを変更できる。
- 「中央へ戻す」は現在のサイズを維持し、「自動再解析」は候補を再計算する。
- 「最大サイズ」は現在位置を基準に拡張し、端にある場合は反対方向へ広げる。
- 座標・サイズを元画像内へ正規化し、表示枠・ハンドルも画像外へ逸脱させない。
- サムネイル取得・加工・埋め込みに失敗した場合は警告を表示し、可能な限り音声保存を継続する。画像を生成できない場合は、JPEGの別保存も省略する。

### 4. 入口と独立ウィンドウ

入口はChromeツールバーの拡張機能アイコンと、視聴ページ内の「NicoPocketで保存」相当のボタンです。ページ内ボタンは共有・ニコニ広告・ギフト等の操作列の下にある右側のアクション領域へ追加し、SPA遷移や再描画後も重複せず復元します。

初回操作で独立ウィンドウを作成し、すでに開いている場合は既存ウィンドウを前面へ移動して対象動画を共通の実行一覧へ追加します。同じ動画を重複登録せず、別動画の追加で編集中の内容を上書きしません。Chrome標準ポップアップとサイドパネルはメインUIに使用しません。

### 5. 保存フローとテーマ

保存フローは次の3段階とし、ステップ表示から移動できるようにします。

1. **基本情報**：対象動画、タイトル・保存名、今回の音質、AAC／JPEG別保存の選択、自動解析済みサムネイルを確認する。
2. **サムネイル**：プレビューとクロップを編集し、候補ごとの編集内容を保持する。
3. **最終確認**：保存内容を確認し、基本情報・サムネイルへ個別に戻って編集する。

保存先はChrome APIから取得できる場合だけ表示し、取得できない場合は項目を表示しません。最終確認からニコニコアカウントの公式利用規約を新しいタブで開けるようにし、規約本文は同梱しません。規約へのリンクを、保存可否の保証として扱いません。

テーマはホワイトを初期値とし、ヘッダーでホワイト／ダークを一時的に切り替えられるようにします。ダークテーマでは本文、状態、秒数、ボタン等の文字色・背景色を一貫して切り替えます。レスポンシブ表示とキーボード操作に対応します。

### 6. 共通の実行一覧

- ユーザー向け名称は「実行一覧」とし、NicoPocket全体で1つの一覧を複数タブから共有する。
- 各項目に「待機中」「処理中」「完了」「警告」「エラー」「キャンセル」を表示する。
- 待機中の項目を削除し、処理中の項目をキャンセルできる。
- エラー・キャンセル済みの項目を再試行し、エラー・キャンセル・完了・警告の項目を削除できる。
- エラー項目には一文程度の概要を表示し、1件の失敗で他の処理を停止しない。
- 一時停止と並び替えは初期要件に含めない。
- 独立ウィンドウを閉じた時点で一覧を消去し、進行中の処理を停止して一時資源を解放する。

同時実行数は初期値10、設定範囲10〜50とします。この値を同数の高負荷Workerを常時起動する指示とは解釈せず、CPU・メモリ・通信・対象サービスへの負荷を検証して安全にスケジューリングします。

### 7. 進捗、通知、エラーと復旧

独立ウィンドウ右上に固定したコンパクトな進捗UIで、工程、全体ゲージ、パーセント、実行一覧内の位置、簡易状態を表示します。工程は音声取得→サムネイル取得→画像解析→音声変換→M4A生成→保存を基本とし、必要な保存と後片付けの終了を確認してから完了とします。

| 状態 | 表示・動作 |
| --- | --- |
| 成功 | 緑系の通知。カウントダウン後に閉じ、「保存されたファイルを開く」を提供 |
| 警告 | 黄系の通知。設定した5秒または10秒後にフェードして閉じる |
| 致命的エラー | 赤系の通知。該当ジョブだけを停止し、概要、詳細ログ、「ログをコピー」を表示 |

エラー概要は一文程度に抑え、技術情報は詳細ログへ分離します。詳細ログはエラー発生時だけ一時保持し、恒久保存は初期要件に含めません。保持上限と機密情報の除外範囲は別途確定します。

保存済みM4Aを開くための `downloads.open` は任意権限とし、ボタン操作時だけ許可を求めます。拒否時も保存結果を維持し、初回許可後は通知を保持して再クリックを案内します。許可済みの場合は1回のクリックで、自拡張機能が保存完了したM4Aを照合して開きます。

保存の停止が確認できない場合は、動画IDとダウンロードIDだけを実行一覧とは別に保持し、ブラウザー再起動後も同じ動画の重複保存を防ぎます。媒体、タイトル、ファイル名、保存先、Blob URLは復旧情報へ保持しません。「保存の終了確認」で自拡張機能のChrome保存履歴を照合し、完了・中断済みと確認してから記録を解除します。履歴なし、処理中、API失敗では記録を維持します。識別子を記録できる前の異常終了への対応は未確定です。

### 8. 保存先、成果物と共通連番

Chrome標準のダウンロード動作と保存前確認の設定を尊重し、独自の保存先入力UIは作りません。保存先内の `NicoPocket/` 直下へ成果物を並べ、ジョブ別・形式別のフォルダーは作りません。

```text
NicoPocket/
├── タイトル.m4a
├── タイトル.aac    （別保存を選択した場合）
└── タイトル.jpg    （別保存を選択し、画像を生成できた場合）
```

同名ファイルには丸括弧の前に空白を入れず連番を付け、同じジョブのM4A／AAC／JPEGは同一のベース名と連番を共有します。JPEGの拡張子は `.jpg` とします。

```text
NicoPocket/タイトル(1).m4a
NicoPocket/タイトル(1).aac
NicoPocket/タイトル(1).jpg
```

最初のM4A保存画面で変更した名前を後続の成果物へ引き継ぎます。保存先を手動変更する場合は各標準保存画面で同じフォルダーを選び、全成果物の名前・場所が揃ってから完了とします。後続の名前・場所が異なる場合は、完了した保存IDを保持して停止します。

専用フォルダーを設けるだけでは共通連番や複数ファイルの一括保存は保証できません。拡張子別の自動連番、履歴外の既存ファイル、外部アプリの同時作成、保存画面での変更・取消し、部分保存を含めた方式全体は検証課題です。共通連番を満たせない場合は、保存方式の再検討が必要です。

### 9. ファイル名の正規化

次の禁則文字候補を半角スペースへ置換し、連続する空白を1つにまとめ、前後の空白を削除します。

```text
\ / : * ? " < > |
```

- UnicodeをNFCへ正規化し、制御文字と表示方向制御文字を除去する。
- Windowsの予約名には `_` を付け、先頭のピリオドと末尾のピリオド・空白を除く。
- タイトル部分は書記素を途中で切らず、UTF-8で200バイト以内に制限し、連番と拡張子の余地を残す。
- 正規化後に空になった場合は、動画IDを保存名に使用する。
- 基本情報画面で正規化後の保存名と禁則文字候補を確認できるようにする。

## 設定の目標値

以下はNicoPocketの設定要件であり、現在のフォーク元の設定項目・初期値ではありません。

| 設定 | 初期値 | 選択肢・範囲 |
| --- | --- | --- |
| デフォルトテーマ | ホワイト | ホワイト／ダーク |
| デフォルト音質 | 最高音質 | 最高音質／160 kbps上限／128 kbps上限 |
| サムネイル画像認識 | ON | ON／OFF。OFF時は中央クロップ |
| AACを別途保存 | OFF | ON／OFF。ジョブ単位でも変更可能 |
| 加工済みJPEGを保存 | OFF | ON／OFF。ジョブ単位でも変更可能 |
| 同時実行数 | 10 | 10〜50 |
| 圧縮失敗時の再試行回数 | 3回 | 1〜5回 |
| 警告表示時間 | 5秒 | 5秒／10秒 |

設定変更は自動保存します。ジョブごとの変更とヘッダーでの一時テーマ切替は、デフォルト設定を変更しません。独立ウィンドウを再度開いたときは永続設定を復元します。

## 技術方針

- Manifest V3の制約に従い、ページ情報取得、タブ間調整、独立ウィンドウ、共通実行一覧、重い処理を責務ごとに分離する。
- 本番の音声変換・画像解析は拡張機能内のWeb WorkerとWebAssemblyで行い、PC上の外部FFmpegやNode.jsを実行時の代替処理基盤にしない。
- JavaScript、Wasm、モデルを拡張機能へ同梱し、実行時にCDNやリモートコードへ依存しない。資産の同梱と外部送信の有無は別に検証する。
- FFmpeg WasmでAAC処理、ストリームコピー・再圧縮、M4A生成、ジャケット・メタデータ書込みを行う。採用コア、ビルド構成、互換性は検証して決定する。
- MediaPipe Object DetectorとEfficientDet-Lite0 int8を画像解析の初期検証候補とする。認識品質、候補評価、個別モデルの再配布条件を確認してから採用する。
- ユーザー向け仕様を保ちながら、Service Workerの停止・再起動に備える。Offscreen Documentの必要性とWorkerとの最終的な責務分担は検証する。
- 必要最小限の権限を採用し、通信先・サイト権限・Wasm実行に必要なCSPを実際の取得経路に合わせて検証する。
- 一時画像、仮想ファイル、Blob URL、Worker、処理メモリをジョブごとに解放する。画像キャッシュは拡張機能内に一時保持し、削除・ウィンドウ終了時に消去する。
- UIを高負荷処理から分離し、画像解析等の付加処理が失敗しても可能な限り音声保存を優先する。
- ビルド基盤・依存バージョンは既存構成を尊重し、独自機能の実現に必要な変更がある場合に採用判断を行う。

## 受け入れ条件

実装後はファイルを生成しただけで完了とせず、保存済みの出力を読み戻して確認します。

- M4Aが再生可能で、想定した音声コーデックになっている。
- 選択した音質上限が実効ビットレートへ反映され、最高音質や上限以下の音源を不要に再圧縮しない。
- 圧縮失敗時の再試行・最高音質への復帰・警告付き継続が要件どおり動作する。
- `title`、`niconico_id`、`source_url` とJPEGジャケットがファイル内に保持される。画像欠損時は警告付き継続として区別する。
- 選択した成果物が同じフォルダー・ベース名・共通連番で保存され、部分保存を全体成功と扱わない。
- Cookie不送信、不要な外部コード読込みの回避、権限の最小化を実通信・実構成で確認する。
- 複数タブ・SPA遷移でも入口と独立ウィンドウを重複させず、候補の編集を上書きしない。
- 1件のエラーが他の実行項目へ波及せず、キャンセル・再試行・削除が正しく動作する。
- 処理後・キャンセル後・ウィンドウ終了後に、一時ファイル、画像キャッシュ、Blob URL、Worker等が解放される。
- 停止未確認の保存を識別子で照合し、確認前の重複保存を防ぐ。
- 独立ウィンドウを再度開いたときに永続設定が復元される。

## 現在のソースをChromeへ読み込む

以下は現在のフォーク元構成を読み込む手順です。NicoPocketの目標UIや独自機能を利用する手順ではありません。

1. このリポジトリのソースを取得する。
2. Chromeで `chrome://extensions/` を開く。
3. 「デベロッパー モード」を有効にする。
4. 「パッケージ化されていない拡張機能を読み込む」で、`manifest.json` が入っている `nico_downloader/` を選択する。
5. 拡張機能のオプション画面を開き、既存の初期設定・保存形式を確認する。フォーク元の初期設定と使用方法は末尾の上流READMEを参照する。

現在のマニフェスト上の表示名は `nico downloader` です。読み込み手順ではビルドを行いません。NicoPocket独自機能の導入・検証手順は、その実装後に更新します。
