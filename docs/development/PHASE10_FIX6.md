# PHASE10 FIX6 — 発行元特定・解消確認・診断撤去

## 原因と実サイト結果

ユーザー提供の実サイト診断ログで、追加AACの発行元は別拡張機能「ニコニコ保存」と確定した。AACの発行元IDはNicoPocketのruntime IDと不一致で、NicoPocket保存ジョブにも対応しなかった。

M4AはNicoPocketが登録した保存ターゲットと一致し、保存完了が確認された。M4Aの発行元IDは空だったため、保存ジョブとの対応を根拠として扱った。

別拡張機能の無効化後、ユーザーがAAC追加保存と設定メニュー表示の問題の解消を確認した。同機能拡張との共存対応は今回行わない。

## 設定メニューの診断

配信元取得に必要なNicoPocketの一時的な設定操作では、設定を開いた後に閉へ戻ることがログで確認された。

別拡張機能のAAC保存開始付近に、NicoPocketの既知の操作識別情報を持たないsynthetic clickが記録された。別拡張機能の無効化で現象は解消したが、相手側の具体的な呼び出し関数までは特定していない。

## 後始末

- 一時診断モジュールとbackgroundでの読み込みを削除。
- Download作成・更新の診断監視、runtime ID確認APIを削除。
- ページのclick capture、設定表示監視、診断用タイマーと状態を削除。
- 配信元操作の診断用ラッパーを外し、元の呼び出しへ戻した。
- 保存・配信元取得・FFmpeg・Metadata・Artwork・音質処理は変更しない。

Chromeの既存セッション内データは、ソースファイルの削除だけでは消去されない。旧診断workerがまだ動いている場合は終了操作で消去できる。診断ログはブラウザセッション終了でも消去される。残る診断開始設定は、コード撤去後は参照されず機能しない。Chrome内の保存データ消去は今回実行していない。
